# 参加履歴画面

[索引](../design-index.md) / [API](../api.md) / [DB](../data-model.md) / [画像](../images.md)

## 目的・ルート・権限

`/history`。user/adminともログイン必須。共通Headerの「参加履歴」から移動します。管理者もこの画面では本人分だけを閲覧します。未認証では `/login` へ転送。参加情報の更新・削除機能はありません。

## 取得と表示

`list_my_submission_history()` を引数なしで呼び、現在回を含む参加済み開催回を開催回作成日時降順、同日時では開催回ID降順に表示します。未参加の回は表示しません。カードは開催回名、現在回の表示、保存されたDiscord名・プロデューサー名、キャラクター、応募部門、初回提出・最終更新日時を表示。日時はブラウザーのタイムゾーンでja-JP形式です。

キャラクター名は開催回の設定、共通名簿、IDの順で解決します。名前と回答は現在保存されている値で、編集前の履歴や開催回設定のスナップショットは保持しません。

| 確認状態 | 得点表示 |
| --- | --- |
| 確認済み・得点あり | 桁区切りの得点。0も表示 |
| 確認済み・得点なし | 得点未登録 |
| 未確認・レビューなし | 確認待ち |
| 無効 | 対象外 |

管理者メモ・確認者はAPIレスポンスに含めません。未確認・無効の得点はDB側でnullにし、画面も状態を確認して表示を制限します。

## 提出画像

結果画像を表示し、旧deckがある場合は評価値（旧形式）・デッキ（旧形式）として分離します。初心者部門または保存パスがある回答ではPID・Pレベル、総出席日数も表示します。パスなしは未提出。

一覧の行または開催回のボタンを選ぶと、モーダルでその回答の提出画像をまとめて表示します。モーダルを開いてから認証付きStorage downloadを行い、Blob URLを表示します。別タブ表示、折りたたみ、取得/画像表示失敗の再試行が可能。閉じる・画面離脱・パス変更・再試行ではBlob URLを解放します。閉じた後に届く古い応答は破棄します。画像のアップロード・編集・削除操作はありません。

## 状態とレイアウト

読込中は状態メッセージ、0件は未参加メッセージと回答入力リンク、失敗は通知と再試行ボタンを表示。再試行では既存リストを消去し、アンマウント後の応答を反映しません。Realtime購読はなく、再訪・ページ再読込で再取得します。

参加情報は画面幅に合わせたテーブルに表示し、幅が収まらない場合はテーブル領域内で横スクロールします。開催回・確認状態・確認済み得点・ユーザー名・プロデューサー名・育成キャラクター・応募部門・初回提出日時・最終更新日時を表示します。開催回のボタンはキーボードでも操作できます。画像モーダルは閉じるボタン・Escape・背景クリックで閉じます。画面冒頭の説明文は表示しません。ライト/ダークは共通テーマへ追従します。

## 検証状況

得点の境界値、現在/過去回、空・失敗・再試行、画像取得・URL解放・遅延応答破棄をコンポーネントテストで確認。DB権限・非公開情報はローカルDBテストで確認。認証・Header遷移はルートテストで確認します。ブラウザーでの描画・PC/スマートフォン操作は接続できるブラウザーがなく検証保留です。[検証記録](../verification.md)を参照してください。
