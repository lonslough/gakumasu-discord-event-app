# 回答入力画面

[索引](../design-index.md) / [DB](../data-model.md) / [画像](../images.md)

## 目的・データ取得

`/entry`、user/adminともログイン必須。get_event_settingsで受付対象の開催回・期間・ルール・2名のキャラクターを取得し、そのevent_idと本人user_idでsubmissionsをmaybeSingle取得します。タイトルは開催回名、ページ画像はentryImageです。この画面に過去回を選択するUIはなく、共通Headerから[参加履歴](history.md)を開いて過去の参加情報・得点・提出画像を確認します。

共通Headerにライト／ダークテーマの切替を表示します。端末連動と保存規則は[共通設計](../architecture.md)を参照します。

## 入力項目

| 項目 | 入力制約 |
| --- | --- |
| サーバー内ユーザーネーム | trim後1〜100文字、必須 |
| ゲーム内プロデューサーネーム | trim後1〜100文字、必須 |
| 育成キャラクター | 開催回設定から選択。enabledまたは既存回答のIDに一致する候補を表示 |
| 応募部門 | open / switch_off / beginner、必須。既存回答があればdisabled |
| 評価値・最終所持スキルカード画像 | 任意、1ファイル |
| PID・Pレベル画像 | beginner時に必須（既存画像で代替可） |
| 総出席日数画像 | beginner時に必須（既存画像で代替可） |

初心者の条件は「参加時点PLv60未満またはログイン日数90日以下」、初心者・switch_offはスイッチカードOFF必須と表示します。数値入力・OCR・ゲームAPIで資格を判定する実装はありません。画像の形式・サイズ・変換は共通画像設計を参照。

## モーダルと状態

- 初回読込中はスピナー。読込完了後、当該回の回答がなければルールモーダルを画面マウントにつき一度自動表示。回答済みは自動表示しない。ボタンから再表示可能。
- ルールは改行を保持し、空の場合は未登録メッセージ。
- 非受付期間は入力fieldsetと送信をdisabled。開始前／終了後をサーバー時刻と設定で区別して通知。
- 期間境界+約1秒で設定を再取得するタイマーを設定。遅延はブラウザー上限2,147,483,647ms以内。
- 送信要求で項目検証し、問題がなければ「送信内容の確認」。新規と上書きで本文を変える。
- 確定後に最新設定を再取得し、受付中なら保存。送信ボタンはsubmittingで無効化。成功は通知、回答再取得、画面上部へスクロール。

## 保存とエラー

entryServiceは既存回答の応募部門を優先し、event_id/user_idをキーにupsertします。新しい画像がなければ現行形式の既存パスを保持。新規・差し替えは画像アップロード→DB参照変更→旧画像削除の順です。新規保存のdeckはnull。旧deckがある回答は結果画像未提出扱いとなり、再保存時に旧score/deckの解消を試みます。

圧縮・アップロード・保存・期間外を固定日本語文言で表示し、失敗時に入力値を維持します。upload/database失敗時は期間を再確認し、受付終了なら期間外メッセージへ変換します。既存画像の取得失敗は画像欄に表示します。

画像選択UIはレビュー状態を取得せず、確認済み/無効でも選択できます。実保存ではDBが画像パス変更を拒否します。キャラクター/結果画像の実差分はレビューを未確認へ戻します。名前変更・初心者証明だけでは戻しません。

## 現行の制限

イベント設定の取得失敗・active回なしではfailureを設定しますが、回答取得が開始されずloadingが残る経路があります。エラー文言を必ず閲覧できるとは限りません。

開催回変更や回答未存在時に既存フォームを明示的に初期化する分岐はありません。送信時の最新event_idと、すでに読み込んだexisting/valuesを併用するため、開いたままの開催回切替を完全に同期する設計ではありません。

## 照合シナリオ（ソース確認）

- 新規／既存／期間外で入力可否・ボタン文言・確認本文が変わる。
- beginnerだけ2画像必須、結果画像は任意。
- 部門固定はUI・保存処理・DBで適用。
- 画像保存失敗時の新画像回収と、成功後の旧画像削除を区別。
- レビュー後の画像制限とレビューリセットは別のDB処理。
